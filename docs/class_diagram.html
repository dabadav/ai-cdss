How to read it

  • Solid arrows (-->) — ownership / composition (one class holds another as an attribute).
  • Dotted arrows (..>) — uses / produces / consumes (data flow without ownership).
  • ..|> — implements a Protocol (PEP 544 structural).
  • $ suffix on a method — static / classmethod.
  • ~ prefix on a field — private (underscore-prefixed in source code).

Where to add a new substrate (e.g. polars)

  1. Write a new class implementing the EngineState protocol (7 methods + 5 properties). Example: PolarsBackedState.
  2. Optionally write the matching SimilarityMatrix adapter.
  3. Either branch in engine.coerce_engine_state so the new type is wrapped automatically, or pass PolarsBackedState(df, pid) explicitly to CDSS.recommend.

No engine algorithm changes. No interface changes. The protocols are the integration point.

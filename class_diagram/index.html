    How to read it¶

    • Solid arrows (-->) = ownership / composition (one class holds another as an attribute).
    • Dotted arrows (..>) = uses / produces / consumes (data flow without ownership).
    • ..|> = implements a Protocol (PEP 544 structural).
    • $ suffix on a method = static / classmethod.
    • ~ prefix on a field = private (underscore-prefixed in code).

    Layers, top to bottom¶

    Layer Class(es) Role
    Public entry CDSS Production wrapper — DB writes, debug artifacts, persistence
    Data ingest Cohort, CohortRepository (Protocol), RGSCohortRepository, ClinicalSubscales, ProtocolToClinicalMapper, DebugReport Repository pattern — assemble one typed Cohort from MySQL + local files
    Offline computations precompute.py (module — 4 pure functions) Compute + persist PPF and protocol similarity from raw inputs (registration / protocol-add workflows)
    Pipeline contracts PreparedInputs, SessionLevelFeatures, ProtocolLevelFeatures, MergedFeatures, ScoringInput, ScoringOutput Typed wrappers around the internal DataFrame stages
    Pipeline orchestrator DataPipeline, Imputer, Scorer Run feature build → impute → score
    Engine protocols EngineState, SimilarityMatrix Substrate-agnostic input contract
    Engine adapters PatientState, DictPatientState, DataFrameSimilarity, DictSimilarity Concrete implementations of the protocols
    Engine core Recommender, ProtocolRow, RecommendationResult, SubstituteResult Recommendation algorithm + introspectable output
    Pandera schemas SessionSchema, PPFSchema, ScoringSchema Inline column-shape documentation (currently no runtime enforcement)

    Cardinality¶

    • One CDSS per process — holds the repository and the pipeline.
    • One CohortRepository per CDSS — production instance is RGSCohortRepository; future implementations (SyntheticCohortRepository, InMemoryCohortRepository) plug in at the same seam.
    • One Cohort per recommendation call — produced by repository.find(patient_ids); consumed by the pipeline + engine.
    • One DataPipeline per CDSS — stateless aside from the imputer / scorer it owns.
    • One Recommender per recommendation call — constructed inline in CDSS._recommend_for_patients_core.
    • One EngineState per patient — created at the Recommender.recommend boundary via coerce_engine_state.
    • One RecommendationResult per (patient, week) — returned from Recommender.recommend, consumed by CDSS._process_patient.

    Where to add a new cohort source¶

    1. Write a new class that implements CohortRepository.find(patient_ids) -> Cohort. Example: SyntheticCohortRepository.
    2. Pass an instance to CDSS(repository=...).

    No pipeline algorithm changes. No engine changes. The protocol is the integration point.

    Where to add a new engine substrate¶

    1. Write a new class that implements EngineState (7 methods + 5 properties). Example: PolarsBackedState.
    2. Optionally write the matching SimilarityMatrix adapter.
    3. Add a branch in engine.coerce_engine_state so a polars input gets wrapped automatically — OR pass an explicit PolarsBackedState(df, pid) to Recommender.recommend.

    No engine algorithm changes. No interface changes. The protocols are the integration point.
